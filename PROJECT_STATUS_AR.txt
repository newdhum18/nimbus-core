NIMBUS CORE V34 — سجل التقدم الكامل القابل للنسخ
====================================================

الحالة العامة:
تم تحويل V33 إلى V34 Resilient Orchestrator مع الحفاظ على Dashboard وAutoScan وSearch وExtract وArchive وSources وTools.

تم تنفيذه بالكامل داخل الكود:
1. Run واحد دائم لكل عملية بحث.
2. منع إعادة فتح Run مكتمل أو Run من نوع/كلمة مختلفة.
3. Source Cursor لا يعود إلى البداية بعد آخر مصدر.
4. حفظ sources_exhausted داخل D1.
5. Resume من نفس run_id والمصدر والطابور.
6. Pause حقيقية في API ومعالج D1 وQueue Consumer والواجهة.
7. إزالة fallback الذي كان يسمح لـRun بمعالجة Queue تخص Run آخر.
8. Stable Task ID موحد بين D1 وCloudflare Queue.
9. إرسال المهام فعلياً إلى Cloudflare Queue مع D1 Shadow للعرض والاستعادة.
10. احتساب enqueued بناءً على الصفوف المضافة فعلياً، وليس عدد المحاولات.
11. Cron كل 5 دقائق لاستعادة Run النشط وزرع الدفعة التالية عند الحاجة.
12. منع إعادة فحص Crawl URLs لمدة 30 يوماً.
13. منع إعادة جلب Source/Search URL نفسه لمدة 30 يوماً.
14. نسبة تقدم Monotonic لا تنخفض عند اكتشاف مهام فرعية جديدة.
15. فصل Scan Progress عن Success Target Progress في الواجهة.
16. مرحلة Discovery حتى 60% ثم مرحلة Queue Draining حتى 100%.
17. Completion لا يحدث إلا بعد انتهاء جميع المصادر وعدم بقاء Pending/Running.
18. Source Task status داخل nimbus_v33_run_tasks يتم تحديثه إلى done/failed.
19. توحيد حالات الصحة: valid / dead / unknown / unverified.
20. عدم اعتبار HTTP 200 وحده دليلاً على صحة مجلد MEGA.
21. قياس Response Time الحقيقي.
22. Circuit Breaker: خمس حالات فشل متتالية = Cooldown لمدة 30 دقيقة.
23. تحديث Config وService Worker وواجهة التطبيق إلى V34.
24. فصل Cache إلى nimbus-v34 لمنع Safari من عرض واجهة قديمة.
25. واجهة Safari أصبحت تراقب Queue الخادم؛ لا ترسل Tick متكرر عند وجود Cloudflare Queue.
26. D1 fallback يبقى متاحاً إذا لم تكن Queue مربوطة.
27. مصادر ON/OFF محفوظة كما هي.
28. كتالوج 1000 سجل محفوظ، مع 84 مصدرًا عالي الاحتمال مفعلاً افتراضياً.
29. Folder-only ورفض file ورفض folder بدون key محفوظة.
30. Redirect decoders وReddit JSON وRaw paste وArchive export محفوظة.
