NIMBUS CORE V34.2 RESILIENT PIPELINE
=====================================

سبب إعادة البناء
----------------
تم تأكيد أن توقف V34 لم يكن سببه D1 أو ربط Queue الأساسي. السبب الجوهري كان أن Queue Consumer يستطيع استهلاك مهام المصدر، لكنه لم يكن يملك Producer binding لإعادة إرسال مهام Crawl الفرعية إلى نفس Queue. بعض المهام الفرعية كانت تحفظ في D1 Shadow Queue فقط، بينما Cron كان يتجنب معالجة D1 عند وجود Cloud Queue. النتيجة: ارتفاع Pending، توقف النسبة، Resume لا يحرك العمل، وظهور No active run مع بقاء مهام.

الإصلاحات المنفذة
-----------------
1. إضافة Producer binding باسم QUEUE إلى Worker المستهلك نفسه.
2. إرسال Crawl child tasks إلى Cloudflare Queue مع D1 Shadow بدل D1 فقط.
3. إبقاء Cron safety drain صغير لمعالجة المهام اليتيمة أو فشل الإرسال المؤقت.
4. احتساب pending/running/leased/retry_wait ضمن تقدم Run.
5. التحقق من Token عند فتح التطبيق وحذف Token المنتهي تلقائياً.
6. إظهار session_expired بدلاً من بقاء الواجهة في unauthorized.
7. جعل Repair DB يعرض حالة واضحة ثم يحدث Dashboard وSources.
8. منع اختفاء قائمة Sources عند فشل طلب مؤقت، والاحتفاظ بالنسخة السابقة.
9. جعل Sources API يطبق سياسة المصادر الصحيحة قبل الإرجاع.
10. تحديث الإصدار وCache إلى V34.2 لتجنب ملفات Safari القديمة.
11. المحافظة على Folder-only ورفض file ورفض folder بدون key.
12. المحافظة على Archive وPause وResume وON/OFF وCron وD1.
