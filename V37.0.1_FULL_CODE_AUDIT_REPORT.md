## Material defects found in V37.0.0 and corrected

1. The Groq-verified ULVIS and Pastebin evidence pages existed only in documentation and were not represented in the operational source catalog.
   - Added both as disabled `custom` candidates.
   - Added Pastemode only as a disabled browser-review candidate.

2. The consolidated `src/db/schema.sql` used an obsolete `links.validation_status` constraint and omitted the final validation columns.
   - Synchronized it with the final migration state.
   - Added a regression test that inserts a `structurally_valid` link with final validation fields.

3. V37.0.0 still fetched MEGA destinations in `src/results/mega-validation.js`, contradicting the approved V37 structural-only/no-MEGA-open boundary.
   - Removed destination fetching.
   - The endpoint now performs structural validation only and returns `structurally_valid` or `invalid`.

4. GitHub deployment verification was labeled and queried only through migration 0014 although migration 0015 was the current schema version.
   - Updated the deployment workflow to verify migration 0015.

5. No source-specific sanitized fixtures existed for the Groq evidence shapes.
   - Added ULVIS, Pastebin, and Pastemode sanitized fixtures and regression tests.

6. The clean baseline SQLite backup was at migration 12.
   - Migrated it through migrations 13, 14, and 15.
   - Synchronized the database schema reference.
